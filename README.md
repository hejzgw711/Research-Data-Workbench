# 生成可分析科研数据工作台

合并工作台：使用原有账号登录，在页面顶部依次切换四个工具。

- 数据反推生成：单因素 / t-test、Two-way ANOVA、重复测量时间序列，保留参数设置、候选、图表、项目打开保存及全部导出。
- WB 灰度测量：目的图与内参图配对、ROI 与泳道调整、旋转、归一化、复制和导出。
- qPCR 数据模拟：分组/重复设计、Cq 与表达量分析、96 孔板、扩增/熔解曲线，以及分析和模拟原始数据的完整下载包。入口位于 WB 和 SPR 之间。
- SPR 数据生成：动力学参数、原始与处理后曲线、表格和完整 Dataset 导出。

同一次登录期间，切换工具保留已经输入的参数、图像和结果；刷新页面仍按各工具原有方式重新初始化。退出登录后回到统一登录页。前端登录门禁与此前一致，只适合减少随意访问，不是服务端安全认证。

四个工具共用顶部操作栏：全局打开、保存、生成、重置和打包导出位于工具导航上方，局部复制和图表操作保留在对应区域。右侧太阳/月亮图标切换统一深浅主题，选择保存在当前浏览器；切换主题不改变输入、计算或导出。

结果图的数值轴按当前数据、误差线和已选比较自动适配，小数值与大数值使用相应精度的简洁刻度。柱图保留零基线，多组/长名称在图内换行或横向滚动；时间序列保留真实时间间距，图例、时间标签和坐标标题分区显示。这些调整仅影响绘图，不改变数值、统计方法或校正方式。

qPCR 使用同源独立页面嵌入，与工作台共用整页滚动和吸顶工具导航，全局按钮呈现在父页面顶部。新建实验默认使用参考波动模型，旧项目仍可精确重放；导出表结构不等同于仪器官方下机文件。直接访问 `/qpcr/` 也返回工作台登录/导航入口，不作为另一个免登录页面。

教学导出不再自动添加“模拟数据 / SIMULATED”等水印、声明、数据类型标记或文件名后缀，网页上的提示保持不变。图表导出只处理系统展示标记，不改用户名称、数值、统计和单位；已知默认项目名在导出时使用中性名称。项目 JSON 仍保留算法版本、随机种子及配置字段以支持重新打开，去掉展示标记并不改变数据来源。

qPCR 参数按原有方式自动保存在当前浏览器。同一电脑的本地预览与线上网站属于不同来源，自动保存不会自动迁移；需要迁移时，在本地“保存”项目 JSON，再到线上 qPCR “打开”该文件。

浏览器本地运行的 Western Blot 灰度测量工具：上传目的条带与内参条带两张图片，框选泳道和背景后，自动测量灰度、按内参归一化，并输出分组统计与柱状图预览。所有图像像素和计算均在当前浏览器内完成，不上传任何图片。

## 本地运行

```bash
pnpm install --frozen-lockfile
pnpm dev
```

预览地址：<http://127.0.0.1:5176/>。

Windows 也可双击 `启动本地预览.cmd`，自动启动并打开网页。使用期间保留启动窗口；关闭窗口或重启电脑后，重新双击即可。已有服务运行时会直接打开页面。

验证命令：`pnpm test`、`pnpm build`、`pnpm test:e2e`。覆盖计算、导出、统一工具栏、主题与窄屏布局；浏览器测试首次运行需 `pnpm exec playwright install chromium`。

生产子目录和线上验收：`node scripts/check-pages.mjs https://hejzgw711.github.io/Research-Data-Workbench/`。该检查仅针对正常运行的新主站，在隔离浏览器中验证原有前端会话协议、四个入口、qPCR 资源及原始工作簿下载，不修改真实用户的浏览器数据。

qPCR 代码在 `src/qpcr/`，`qpcr/index.html` 与根页面由一次 Vite 构建产出，原 GitHub Pages 流程不变。qPCR 的嵌入登录检查在独立 `main.tsx`，计算与导出模块沿用已经验证的独立版本。不要将个人参考 XLS、自动保存记录或运行时目录复制到发布仓库。

旧地址 https://hejzgw711.github.io/wb-gray-studio/ 和 https://hejzgw711.github.io/synthetic-stat-studio/ 暂停工具服务，入口显示“ny正在迭代牛逼功能，敬请期待”。旧仓库源码及历史保留，Pages 只发布静态维护页面，不发布工具脚本；不会清除用户浏览器中的项目或登录记录。

本地 `origin` 对应新主站仓库 `hejzgw711/Research-Data-Workbench`，`legacy-wb` 对应旧仓库 `hejzgw711/wb-gray-studio`。后续经用户确认发布时仅推送 `origin/main`；不要再把主站源码同步推送到旧站，否则可能意外恢复已暂停的工具。未要求上线的修改仅保留在本地。

恢复旧站需要用户明确要求，再还原对应仓库的维护提交并重新发布。三个路径仍属于同一 GitHub Pages 来源，主站继续沿用原账号密码以及已有的浏览器本地存储。
